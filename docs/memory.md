# Archivist во внешней памяти

Многие пользуются долгосрочной памятью агентов: OpenViking, mem0 и другими. Archivist кладёт туда знания проекта, чтобы их видели и другие агенты и плагины, а не только Claude Code в этом репозитории. Этот документ описывает, как он это делает. Другой плагин может по нему находить, читать и не ломать записи Archivist.

## Принцип: журнал — истина, память — проекция

1. **Единица — запись.** Каждая действующая запись (команда, ловушка, решение, процедура) — один элемент памяти. Текст самодостаточен: его понимает агент, который ничего не знает об Archivist.
2. **Устойчивый ключ** `archivist/<проект>/<id записи>`.
   - Проект берётся из `git remote get-url origin`, сведённого к `host/owner/repo` (без учётных данных и порта), поэтому совпадает на всех машинах. Если remote нет — `local/<имя папки>`.
   - Где система памяти даёт выбрать адрес, ключ и есть адрес. Где она выдаёт свой id, адаптер ищет элемент по ключу перед добавлением, так что дублей не появляется.
3. **Подпись.** Последняя строка элемента: `Project: <проект> · Archivist <id> · updated <время>` (у решений ещё `ADR-NNNN`). По ней копия Archivist узнаёт свой элемент и видит, чья версия новее.
4. **Дословно.** Факт уже отобран, поэтому пишется без переписывания через LLM. Режимы «извлечения» (`remember`, `infer: true`) не используются.
5. **Сведение к журналу.** Одно пространство делят клоны, worktree, ветки и коллеги с общим сервером памяти, поэтому:
   - элемент пишется, когда изменилась своя запись, или когда эта копия видит запись впервые, а в памяти её нет или там версия старше;
   - более новую по `updated` версию Archivist никогда не перезаписывает;
   - удаляет только элементы записей, которые его журнал вывел из оборота, кто бы их ни писал;
   - пропавший элемент не восстанавливает, а сообщает о нём;
   - элементы, которых нет в его журнале, не трогает;
   - запись, у которой пропали доказательства (файлы), не пишет и не удаляет: они могли пропасть только в одной ветке.
6. **Кэш и сверка.** Что отправлено из этой копии, лежит в `.archivist/.local/memory-<хранилище>.json`. Обычная синхронизация сравнивает журнал с кэшем и память не читает. С памятью она сверяется при старте сессии и когда кэш пуст (новый клон или worktree).
7. **Своё пространство.** Писать и удалять Archivist может только свои подписанные элементы, а читать — всю память.
8. **Транспорт.** Archivist ходит в память через MCP-сервер уже подключённого плагина памяти: его соединением и ключами, своих кредов у Archivist нет.

## OpenViking

Сейчас поддерживается OpenViking.

- Адрес элемента: `viking://resources/archivist/<host>/<owner>/<repo>/<id>.md`.
- Запись — `write` (`mode: "replace"`), удаление — `forget`, список — `list`, чтение — `read`.
- Recall плагина OpenViking показывает такие ресурсы аннотацией, полный текст агент дочитывает через `read`.

Элемент выглядит так:

```
# Mod code has no Node types

Gotcha: Typecheck it with `tsc -p tsconfig.mod.json`
Why: the mods runtime has no Node
Where: src/adapters/**

Project: github.com/owner/repo · Archivist gk-1a2b · updated 2026-10-23T10:00:00.000Z
```

## Другие системы памяти

Адаптер — это небольшое соответствие операций Archivist инструментам системы. Если система чего-то не умеет, Archivist этот шаг пропускает.

| Операция | OpenViking | mem0 | Файловая память (basic-memory, Serena) | Графовая память (MCP memory) |
|---|---|---|---|---|
| записать | `write` по адресу | найти по `metadata.archivist_key`, затем `update` по UUID или `add` с `infer: false` | файл `archivist/<проект>/<id>.md` | сущность `archivist:<проект>:<id>`, строки элемента как наблюдения |
| удалить | `forget` | `delete` по UUID | удалить файл | удалить сущность |
| список | `list` папки проекта | поиск с фильтром по `metadata.project` | список папки | сущности с префиксом |
| прочитать | `read` | `get` по UUID | прочитать файл | открыть сущность |

## Настройки и команды

```json
"memory": { "enabled": true, "server": "auto", "project": "auto" },
"rules": { "files": true }
```

- `memory.enabled` — синхронизировать, когда в сессии подключён поддерживаемый плагин памяти.
- `memory.server` — `auto` или имя сервера, как его показывает `/mcp`.
- `memory.project` — `auto` или своё имя проекта.
- `rules.files: false` — не создавать файлы правил и skills для Claude Code, знания идут только в память. `INDEX.md` и ADR остаются.
- `/archivist memory` — куда идут записи и что с ними. `/archivist memory sync` — сверить сейчас. `/archivist memory clear` — убрать свои элементы проекта из памяти.

Выключение синхронизации и `archivist uninstall` из памяти ничего не удаляют: удаление там необратимо, поэтому оно делается только явной командой `clear`.

## Что дальше

- Чтение: куратор будет видеть в ресурсах памяти факты других агентов и не дублировать их, а `/archivist recall` начнёт искать и в памяти.
- Сверка при старте сессии: правка элемента другим агентом уйдёт в ревью как предложение, а элементы чужих веток можно будет убрать командой `/archivist memory prune`.
