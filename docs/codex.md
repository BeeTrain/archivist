# Archivist для Codex: знания и фоновый анализ

Пакет: `plugin-codex/`. Формат — `.codex-plugin/plugin.json`, навыки и command hooks. Нужен Node.js ≥ 20 в среде выполнения Codex.

Поддерживаются ручное сохранение знаний, сбор метаданных и фоновый анализ задач через установленный Codex CLI. Анализ включается отдельно для проекта; по умолчанию выключен. Отдельный API-ключ не требуется.

## Что подключается

- `panel`: живая панель рядом с чатом — количество активных записей, очередь ревью, просмотр и поиск. Обновляется каждые три секунды.
- `setup`: инициализация проекта и диагностика.
- `remember`, `decide`, `triage`: общие операции над базой знаний.
- `recall`: поиск релевантных записей перед разведкой проекта.
- `collection`: состояние сбора данных и разбор текущей задачи через доступный контекст чата.
- Hooks: SessionStart, UserPromptSubmit, PostToolUse, Stop, Interrupt, SessionEnd.

При SessionStart плагин пересобирает представления и передаёт короткий core-контекст. Scoped-записи доступны через recall; их glob-frontmatter хранится как метаданные, автоматическая загрузка по glob в Codex не заявляется.

## Панель рядом с чатом

Попросите «Открой панель Archivist» или вызовите навык `panel`. Он запускает локальный процесс и открывает панель во встроенной вкладке Codex. Панель показывает активные записи и предложения на ревью; нажатие на счётчик переключает список, поле поиска фильтрует его. Применение предложений выполняется через навык `triage` в чате.

Для ручного запуска: `node plugin-codex/bin/archivist panel --root <каталог-проекта>`. Откройте напечатанный адрес и оставьте процесс работающим. Остановка процесса отключает обновление панели; интерфейс сообщает о потере связи. Чтобы завершить ручной запуск, нажмите Ctrl+C. Сервер слушает только локальный адрес, использует случайный адрес доступа и не изменяет базу знаний. Адрес не сохраняйте в коммитах.

## Подключение

Установить опубликованный пакет:

```bash
codex plugin marketplace add BeeTrain/archivist
codex plugin marketplace upgrade archivist
codex plugin add archivist-codex@archivist
```

Каталог `.agents/plugins/marketplace.json` указывает на пакет `plugin-codex/` из тега выпуска. Сборка при установке не требуется. Для обновления выполните последние две команды снова.

Затем включите плагин и проверьте/доверьте его hooks в настройках Codex. Вызовите навык setup в нужном проекте. Начните новый чат, выполните несколько инструментов и завершите ход. Вызовите collection для проверки доставки событий.

Для разработки: `npm ci && npm run build && npm run validate:codex`. Установка в пользовательский профиль не выполняется сборкой. Установленный пакет загружается из кэша; изменения исходников не меняют опубликованную установку.

Документация платформы: [упаковка и локальные marketplaces](https://developers.openai.com/plugins/build/plugins), [hooks и доверие](https://learn.chatgpt.com/docs/hooks).

## CLI

```bash
node /absolute/path/to/plugin-codex/bin/archivist init --root /path/to/project
node /absolute/path/to/plugin-codex/bin/archivist doctor --root /path/to/project
node /absolute/path/to/plugin-codex/bin/archivist recall build --root /path/to/project
node /absolute/path/to/plugin-codex/bin/archivist collection
```

`collection` использует текущую директорию проекта. Остальные команды поддерживают `--root`. Общий CLI также принимает `--target codex`; пакет Codex выбирает этот профиль сам.

## Фоновый анализ

Из папки проекта выполните:

```bash
node /absolute/path/to/plugin-codex/bin/archivist analysis enable
node /absolute/path/to/plugin-codex/bin/archivist analysis status
```

После завершения хода и 90 секунд тишины запускается отдельный процесс Codex. Новое сообщение откладывает анализ; начавшийся вызов отменяется, устаревший результат отбрасывается. Дайджест составляется из полей `prompt`, `last_assistant_message` и метаданных инструментов, предоставленных хуками. Транскрипты не читаются. Если текста запроса нет, задача отмечается как недостаточно обеспеченная контекстом и модель не вызывается.

Все изменения знаний поступают на ревью, включая обновления и подтверждения существующих записей. Автоприменение и продвижение по повтору отключены. Панель показывает состояние анализа и количество предложений.

Настройки в `.archivist/config.json`:

```json
{
  "codex": {
    "enabled": true,
    "model": "",
    "timeoutSeconds": 120,
    "maxCallsPerDay": 20
  }
}
```

Пустая модель использует стандартную модель отдельного запуска CLI. `analyzer.idleSeconds` задаёт паузу. Вызовы расходуют лимиты аккаунта; при недоступной авторизации анализ завершается ошибкой. Перехода на отдельный платный API нет. В дочернем запуске отключены пользовательская конфигурация, хуки, плагины, команды, поиск и подключённые приложения; рабочая папка — временная, режим доступа — только чтение. Вывод проверяется по схеме, результат с вызовами инструментов отклоняется.

Очередь и дневной счётчик вызовов сохраняются в `.archivist/.local/codex/`. Процессы одного проекта используют блокировку с heartbeat. Ошибка повторяется через 15 минут, максимум три попытки. Дневной токенный бюджет берётся из `analyzer.maxTokensPerDay`; перед вызовом резервируется 50 000 условных токенов, после успешного ответа резерв заменяется фактическим расходом. Если расход неизвестен, резерв остаётся. Это ограничение запусков, а не гарантия верхней границы стоимости ответа. Данные об оставшихся окнах лимитов аккаунта заранее недоступны; ошибки сервиса обрабатываются как ошибки вызова.

`analysis disable` выключает дальнейший анализ, сохраняя очередь и записанный контекст. `analysis run` запускает обработчик очереди вручную; он соблюдает время ожидания и бюджеты. При следующем SessionStart или завершении хода обработчик подбирает оставшиеся задачи.

## Данные и приватность

Общий источник истины — `.archivist/ledger.jsonl`. ADR и очередь ревью совместимы с Claude. Codex-представления находятся в `.archivist/codex/rules/`, процедуры — в `.agents/skills/archivist-*/`. Представления Claude обновляются его адаптером; Codex их не удаляет.

События сохраняются отдельными файлами в `.archivist/.local/codex/events/<hash-session>/`. Каталог автоматически добавляется в локальный gitignore. Идентификаторы сессий, ходов и вызовов хешируются. Повторная доставка инструмента с тем же tool_use_id не создаёт дубликат.

Сохраняются время, тип события, имя инструмента, имена полей payload и относительные пути из заголовков apply_patch с учётом privacy.excludePaths. При выключенном анализе тексты промптов, ответов, команд, патчей, результатов и транскрипты не сохраняются. При включённом анализе в `tasks/` сохраняется ограниченный дайджест: запросы, итоговые ответы, цели инструментов и краткие ошибки команд. Патчи и полные результаты инструментов не сохраняются. Перед записью секреты маскируются, строки с исключёнными путями отбрасываются.

Диагностические события остаются на машине. При явно включённом анализе очищенный дайджест и релевантные записи передаются модели через Codex. Ротация файлов пока отсутствует: следить за объёмом каталога. Экспортировать набор для разбора только после проверки на приватность.

`uninstall` удаляет только сгенерированные представления выбранной платформы. `--purge` удаляет общую базу `.archivist/`, включая данные Claude и локальный сбор; применять только при намерении полностью удалить знания проекта.

## Проверки и ограничения

Проверены тесты нормализации, исключение содержимого, дедупликация, изоляция представлений и вызов обработчика в временном проекте. Валидатор пакета проверяет структуру и пути, но не заменяет загрузку плагина клиентом Codex. Живая установка и действительные payload установленной версии должны быть проверены при подключении.

Формат payload может различаться между клиентами. Полнота дайджеста зависит от доступных полей хуков; результаты работы подагентов и содержимое вложенных вызовов инструментов не реконструируются автоматически.
