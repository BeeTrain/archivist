# Archivist

Плагин для Claude Code, который учится на каждой задаче агента. После задачи он разбирает сессию и записывает в проект то, что агенту дорого переоткрывать: точные команды, неочевидные ловушки и принятые решения с причинами. В следующих сессиях агент получает эти записи сразу и тратит меньше времени, токенов и контекста на разведку.

Статус: **v1.3**. Работает с Claude Code ≥ 2.1.290: терминал, десктоп, VS Code. План развития — в [PLAN.md](PLAN.md), результаты исследования платформы — в [docs/spikes.md](docs/spikes.md).

## Как это работает

1. **Во время задачи** мод ведёт журнал: промпты, вызовы инструментов (только цели, без содержимого), ошибки команд, загруженные правила Archivist, токены каждого хода. Модель при этом не вызывается.
2. **Когда сессия затихла** (по умолчанию через 90 с после хода), запускается фоновый анализ:
   - детерминированно считаются сигналы потерь: чтения до первой правки, повторные чтения, упавшие и потом исправленные команды, поправки пользователя;
   - тривиальные задачи пропускаются, большинство задач не должно ничего порождать;
   - **reflect**: основной модели задаётся короткий вопрос поверх её же транскрипта (`$.model.fork`, контекст берётся из prompt cache);
   - **curate**: haiku превращает заметки в дельта-операции над записями (`add` / `update` / `reinforce` / `deprecate`), видя только самые релевантные существующие записи;
   - **validate**: детерминированный код отбрасывает дубли и то, что уже написано в README/CLAUDE.md, проверяет ссылки на файлы и решает, что применить сразу, а что отправить на ревью.
3. **Самопроверка**: каждая задача измеряется (токены, вызовы инструментов, чтения до первой правки, повторные чтения, упавшие команды). Записи получают счётчики: правило загрузилось, записанная команда выполнилась, агент сказал, что запись помогла или ввела в заблуждение. Запись, которая чаще вредит, чем помогает, предлагается на удаление; давно неиспользуемые находит `archivist gc`.
4. **Отчёт**: короткий итог в статус-строке («📚 +2 entries · 1 to review»), toast, строка под следующим ответом и полный отчёт по команде `/archivist`.

Все вызовы модели идут через авторизацию самой сессии. Отдельный API-ключ и логин в CLI не нужны.

## Что появляется в проекте

```
.archivist/
  ledger.jsonl            журнал операций, источник истины (только дописывается)
  INDEX.md                одна строка на запись
  decisions/ADR-NNNN-*.md решения в формате ADR
  config.json             настройки
  .local/                 только на этой машине (в .gitignore):
    reports/*.md          отчёт по каждой задаче: цитирует промпты, id сессии, расход токенов
    proposals/*.json      неуверенные изменения, ждут ревью
    metrics.jsonl         метрики каждой задачи; baseline.json — то же по сессиям до Archivist
    usage.json            как часто каждая запись встречалась, применялась, помогала или вводила в заблуждение
    analyses.jsonl        каждый запуск анализа: исход, сколько записано, стоимость, ошибки
.claude/rules/archivist/
  core.md                 то, что агент читает в начале каждой сессии (не больше 60 строк)
  <area>.md               факты для части кода, с `paths:` во frontmatter: Claude Code загружает файл,
                          только когда агент открывает подходящие файлы (не больше 40 строк)
.claude/skills/archivist-*/SKILL.md
                          повторяющиеся процедуры (релиз, миграция): skill появляется только после
                          второго повтора и ревью
```

Все эти файлы, кроме `ledger.jsonl` и `config.json`, генерируются из журнала, руками их не правят. `.archivist/` и `.claude/rules/archivist/` стоит коммитить: тогда знания доступны всей команде. Что принадлежит сессии (промпты, id сессий, расход токенов), остаётся в `.archivist/.local/` и в git не попадает: в журнал пишется только сам факт, доказательство в коде и id сегмента задачи. В `core.md` попадают только команды, ловушки и ссылки на решения. Обзоров кодовой базы там нет, потому что они не ускоряют агента и удорожают каждую сессию ([почему](PLAN.md#13-эмпирика-что-реально-экономит-ресурсы)).

## Установка

Нужны Claude Code ≥ 2.1.290 (терминал, десктоп или VS Code) и Node ≥ 20 для CLI и skills. В сессии Claude Code:

```
/plugin install archivist --marketplace BeeTrain/archivist
```

Или в два шага: `/plugin marketplace add BeeTrain/archivist`, затем `/plugin install archivist@archivist`. После установки выполни `/reload-plugins` или начни новую сессию.

Подготовка проекта (необязательно): создаёт `.archivist/` и записывает точные команды сборки, тестов и линта из `package.json`, `Makefile`, `justfile`, `Cargo.toml`, `go.mod`. Агент может сделать это сам, а вручную CLI лежит в каталоге плагина: `archivist init` из Bash-инструмента сессии, где `bin/` плагина есть в PATH.

Удаление: `archivist uninstall` убирает сгенерированные правила и skills (написанное руками не трогает), `--purge` удаляет ещё и `.archivist/`. Затем `/plugin uninstall archivist@archivist`.

### Из исходников

```bash
npm install
```

```bash
npm run build
```

Сборка обновляет `plugin/hooks/register.js` (мод) и `plugin/bin/archivist` (CLI); оба файла лежат в git, потому что установка из маркетплейса ничего не собирает. Запуск Claude Code с плагином из рабочей копии:

```bash
claude --plugin-dir ./plugin
```

В десктоп-приложении путь к `plugin/` передаётся через переменную `CLAUDE_CODE_PLUGIN_DIRS`.

## Команды

В сессии Claude Code:

| Команда | Что делает |
|---|---|
| `/archivist` | полный отчёт по последней проанализированной задаче |
| `/archivist status` | сколько записей по типам, сколько ждёт ревью, есть ли открытая задача |
| `/archivist:triage` | skill: агент сам проверяет технические предложения по коду и разбирает их, а тебя спрашивает только про решения и удаления |
| `/archivist review` | предложения, которые анализатор не решился применить сам |
| `/archivist apply <n\|1,3\|all>` | записать предложения как есть |
| `/archivist skip <n\|1,3\|all>` | отклонить; та же идея больше не предлагается |
| `/archivist health` | одна сводка о работе в этом проекте: база, анализы за неделю, сбои, расход, какие записи не используются, находки `lint` — и что сделать |
| `/archivist stats` | метрики последних задач против baseline и как работает каждая запись |
| `/archivist recall <слова>` | записи по теме: дешевле, чем искать по коду |
| `/archivist edit <id> [--title "…"] [--content "…"] [--why "…"] [--paths "…"]` | поправить записанное; пустой `--paths ""` снимает привязку к путям |
| `/archivist deprecate <id> --reason "…"` | вывести запись из правил (в журнале остаётся с причиной) |
| `/archivist log` | диагностика фонового анализа в текущем проекте |
| `/archivist:remember [что]` | skill: записать команду или ловушку вручную |
| `/archivist:decide [что]` | skill: записать решение как ADR (с причиной и отвергнутыми вариантами) |

В терминале (`plugin/bin/archivist`, пока плагин включён, он доступен агенту в PATH как `archivist`):

| Команда | Что делает |
|---|---|
| `archivist init` | создаёт `.archivist/` и записывает команды из манифестов проекта |
| `archivist status` | состояние базы знаний |
| `archivist report [file]` | последний отчёт или указанный |
| `archivist review [--json]` / `apply <n\|id>` / `skip <n\|id>` | ревью предложений, как в сессии; `--json` и id — для разбора агентом |
| `archivist add --type <command\|gotcha\|decision> --title … --content … [--why …] [--paths …] [--evidence …]` | записать факт вручную; решению нужен `--why` |
| `archivist edit <id> …` / `deprecate <id> --reason …` | поправить или вывести запись, как в сессии |
| `archivist recall <слова>` | поиск по записям (BM25); агент может вызывать сам, вместо разведки |
| `archivist baseline [--before <дата>]` | метрики сессий Claude Code этого проекта до Archivist, из их транскриптов |
| `archivist health` | то же, что `/archivist health`, без лога мода (его видит только сессия) |
| `archivist stats` | медианы последних задач против baseline, оценка экономии против наблюдаемой, использование записей |
| `archivist gc [--days 60] [--apply]` | записи без признаков использования за срок; `--apply` выводит их из правил (в журнале остаются) |
| `archivist lint` | дубли и противоречия, stale, решения без причины, переполнение бюджета |
| `archivist render` | перегенерирует представления из журнала |
| `archivist doctor` | проверяет Node, версию Claude Code, конфиг, журнал и бюджеты файлов правил |
| `archivist uninstall [--purge]` | убирает сгенерированное Archivist; `--purge` — и `.archivist/` |

## Настройки

`.archivist/config.json` (значения по умолчанию):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | выключатель для проекта |
| `language` | `"auto"` | язык записей: `auto` — как в промптах пользователя, иначе например `"Russian"` |
| `analyzer.idleSeconds` | `90` | сколько тишины после хода считать концом задачи |
| `analyzer.minToolCalls` | `5` | порог: задачи меньше этого без правок и ошибок пропускаются |
| `analyzer.reflect` | `"fork"` | `fork` — спросить основную модель поверх её контекста; `digest` — только haiku по дайджесту |
| `analyzer.forkMaxContextTokens` | `300000` | при большем живом контексте reflect идёт по дайджесту, без `fork`: цена `fork` растёт с сессией |
| `analyzer.curateModel` | `"haiku"` | модель для курирования |
| `analyzer.maxTokensPerDay` | `3000000` | дневной бюджет анализа во взвешенных токенах (чтение из кэша считается как 0.1) |
| `analyzer.maxRateLimitPercent` | `90` | не анализировать, если окно лимита заполнено сильнее |
| `apply.autoConfidence` | `0.8` | порог уверенности для применения без ревью |
| `apply.autoTypes` | `command, gotcha, decision` | какие типы можно применять без ревью |
| `budgets.coreLines` | `60` | лимит строк `core.md` |
| `budgets.pathFileLines` | `40` | лимит строк каждого файла правил для части кода |
| `privacy.excludePaths` | `.env*`, `**/secrets/**`, `**/*.pem`, … | файлы, которые не попадают ни в журнал, ни в модель, ни в доказательства записей |
| `report.mode` | `"quiet"` | `quiet` — статус, toast, строка под ответом; `rewake` — сессия получает ход с отчётом (стоит один короткий ход модели) |
| `report.toastMs` | `15000` | сколько держится toast |
| `review.promoteOnRepeat` | `true` | команда или ловушка, предложенная повторно, пока первое предложение ждёт, применяется сама |
| `review.expireDays` / `review.expireTasks` | `14` / `20` | неразобранные предложения удаляются через столько дней или задач |

## Разбирать очередь не обязательно

На ревью уходит то, в чём анализатор не уверен: неуверенные факты, процедуры, записи с замаскированными секретами, решения и удаления. Вникать в каждое предложение не нужно:

- **`/archivist:triage`** — агент проверяет команды и ловушки по коду и разбирает их сам. Тебя он спрашивает только о решениях и удалениях, по строке на понятном языке.
- **Повтор подтверждает.** Если команду или ловушку предложили снова, пока первое предложение ждёт, она записывается сама: два независимых наблюдения надёжнее одной оценки уверенности. Решения и удаления так не применяются.
- **Срок жизни.** Неразобранное предложение удаляется через 14 дней или 20 задач. Важный факт всплывёт снова и запишется по повтору, так что очередь можно просто игнорировать.

## Стоимость и приватность

- Анализ запускается один раз на задачу и только для нетривиальных задач. Расход каждого шага указан в отчёте и учитывается в дневном бюджете.
- `fork` читает уже закэшированный контекст сессии: платится чтение из кэша (≈ 0.1 от обычного входа) и короткий ответ. Курирование на haiku стоит единицы тысяч токенов.
- То, что принадлежит сессии (`.archivist/.local/`: отчёты с текстом промптов, id сессий, метрики), в git не попадает: первая же запись в `.archivist/` создаёт `.archivist/.gitignore` со строкой `.local/`, даже если `archivist init` не запускали.
- Данные никуда, кроме API модели вашей же сессии, не отправляются. Телеметрии нет. В журнал попадают цели инструментов (пути, команды), а не содержимое файлов.
- Секреты (ключи API, токены, пароли в присваиваниях, приватные ключи, пароли в URL) маскируются в командах журнала, в материале для модели и в тексте записей. Запись, для которой понадобилось маскирование, уходит на ревью.
- Записи с исчезнувшими доказательствами (файлы удалены или переименованы) помечаются в `INDEX.md` как stale и не попадают в правила, пока файл не вернётся или запись не обновят.

## Разработка

```bash
npm run check
```

`check` запускает проверку типов в двух конфигурациях: с Node для CLI и в окружении мода без Node, по типам `types/claude-code/`. Затем идут тесты (vitest) и сборка. Валидация плагина:

```bash
npm run validate
```

Eval-кейсы лежат в `plugin/evals/`:
- ловушка записывается и привязывается к путям;
- решение становится ADR;
- личное и временное не записывается;
- секрет не попадает в файлы.

Прогоны тратят лимиты твоей подписки, `claude` должен быть залогинен. Skills вызывают CLI через Bash, поэтому его нужно разрешить:

```bash
claude plugin eval plugin --allow-tools Bash
```

Фоновый анализ мода eval не покрывает: прогоны идут в `claude -p`, а анализ запускается по таймеру после простоя. Его проверяют вживую через `/archivist log` и `/archivist stats`.

CI (`.github/workflows/ci.yml`) гоняет проверку типов, тесты и сборку, проверяет, что собранный плагин закоммичен, и валидирует плагин и маркетплейс.

Структура:

```
src/core/       модель данных, журнал, валидация, рендер — чистый TS без Node (используется и модом, и CLI)
src/analyzer/   сигналы, дайджест, промпты, разбор ответа модели, пайплайн, отчёт
src/adapters/claude/mod/register.ts   мод Claude Code: события → журнал → анализ → отчёт
src/cli/        CLI на Node
plugin/         собранный плагин (манифест, hooks.json, register.js, bin/)
spikes/         код исследований этапа 0
```

Ограничения среды мода, которые важны при правках `register.ts`:
- в моде нет Node, весь ввод-вывод идёт через `$`;
- `$` можно передавать только функциям верхнего уровня этого файла;
- имя события в `on()` должно быть литералом;
- имена команд мода не получают префикс плагина;
- при перезагрузке мода сбрасываются таймеры.

Подробнее — в [docs/spikes.md](docs/spikes.md).
