# Archivist

Archivist — плагин для **Claude Code, Codex и OpenCode**, который сохраняет знания из задач агента: точные команды, неочевидные ловушки и принятые решения с причинами. В следующих сессиях агент получает эти записи и тратит меньше времени, токенов и контекста на разведку. Все версии используют общую базу знаний проекта; в Claude Code и OpenCode фоновый анализ работает после подключения, а в Codex включается отдельно для проекта. Codex и OpenCode отправляют все результаты анализа на ревью.

Статус: **v1.7.0**. Для Claude Code ≥ 2.1.290 (терминал, десктоп, VS Code) пакет находится в `plugin/`, для Codex с поддержкой плагинов и command hooks — в `plugin-codex/`. Адаптер для OpenCode **2.2.5 (V2)** находится в `plugin-opencode/`, подключается локально из репозитория. Нужен Node.js ≥ 20; фоновому анализу Codex также нужен установленный и авторизованный Codex CLI. План развития — в [PLAN.md](PLAN.md), устройство мода Claude Code — в [docs/spikes.md](docs/spikes.md), особенности Codex — в [docs/codex.md](docs/codex.md), особенности OpenCode — в [plugin-opencode/README.md](plugin-opencode/README.md).

## Как это работает

1. **Во время задачи** плагин собирает контекст без вызова модели. В Claude Code мод ведёт журнал промптов, целей инструментов, ошибок команд, загруженных правил и токенов каждого хода. В Codex hooks по умолчанию сохраняют только метаданные событий; при включённом анализе — ещё ограниченный дайджест запросов, итоговых ответов, целей инструментов и кратких ошибок. Транскрипты Codex не читаются. В OpenCode собираются очищенные запросы и ответы основной сессии, цели инструментов, краткие ошибки и метрики; содержимое прочитанных файлов, патчи и рассуждения модели не сохраняются.
2. **Когда сессия затихла** (по умолчанию через 90 с после хода), запускается фоновый анализ. В Claude Code:

   - детерминированно считаются сигналы потерь: чтения до первой правки, повторные чтения, упавшие и потом исправленные команды, поправки пользователя;
   - тривиальные задачи пропускаются, большинство задач не должно ничего порождать;
   - **reflect**: основной модели задаётся короткий вопрос поверх её же транскрипта (`$.model.fork`, контекст берётся из prompt cache);
   - **curate**: haiku превращает заметки в дельта-операции над записями (`add` / `update` / `reinforce` / `deprecate`), видя только самые релевантные существующие записи;
   - **validate**: детерминированный код отбрасывает дубли и то, что уже написано в документации проекта, проверяет ссылки на файлы и решает, что применить сразу, а что отправить на ревью.

   В Codex анализ по умолчанию выключен. После включения отдельный процесс Codex CLI обрабатывает очищенный дайджест; все изменения, включая обновления и подтверждения записей, идут на ревью. Новое сообщение откладывает анализ, а устаревший результат отбрасывается.

   В OpenCode анализ включён по умолчанию. После завершения задачи и паузы сервер делает отдельный вызов модели без инструментов и записи в историю чата. Используется модель сессии или явно заданная `opencode.model`; очищенный дайджест проходит общий анализатор и проверку. Все изменения отправляются на ревью. Новый запрос отменяет ожидание и устаревший анализ; очередь и дневные лимиты сохраняются при перезапуске.
3. **Самопроверка**: Claude Code измеряет каждую задачу (токены, инструменты, чтения и ошибки) и использование записей: правило загрузилось, команда выполнилась, агент сообщил о пользе или ошибке. В Codex навык `collection` показывает доставку событий и состояние анализа; в OpenCode состояние очереди видно в панели и через `analysis status`. Сравнение с baseline сессий для Codex и OpenCode пока недоступно. Общий CLI проверяет знания через `lint` и находит давно неиспользуемые записи через `gc`.
4. **Отчёт**: в Claude Code — короткий итог в статус-строке («📚 +2 entries · 1 to review»), toast, строка под следующим ответом и полный отчёт по `/archivist`. В Codex — живая панель рядом с чатом: записи, поиск, очередь ревью и состояние анализа. Её открывает навык `panel`; предложения разбирает навык `triage`. В OpenCode Desktop — индикатор 📚 над полем ввода и панель с записями, поиском, ревью и последним отчётом. Она открывается по индикатору или `/archivist-panel`; предложения можно принять или отклонить прямо в ней. После анализа появляется уведомление. Обновление интерфейса не вызывает модель.

Отдельный API-ключ для Archivist не нужен. Claude Code использует авторизацию самой сессии, Codex — авторизацию установленного Codex CLI, OpenCode — настроенного в нём провайдера модели. Вызовы анализа расходуют лимиты соответствующего аккаунта или оплачиваются по тарифу провайдера.

## Что появляется в проекте

```
.archivist/
  ledger.jsonl            журнал операций, источник истины (только дописывается)
  INDEX.md                одна строка на запись
  decisions/ADR-NNNN-*.md решения в формате ADR
  config.json             настройки
  codex/rules/            представления знаний для Codex: core.md и записи для частей кода;
                          core передаётся при SessionStart, остальные доступны через recall
  opencode/rules/         представления знаний для OpenCode: общие и привязанные к путям правила;
                          контекст перед запросом модели формируется из актуальной базы
  .local/                 только на этой машине (в .gitignore):
    reports/*.md          отчёт по каждой задаче: цитирует промпты, id сессии, расход токенов
    proposals/*.json      неуверенные изменения, ждут ревью
    metrics.jsonl         метрики каждой задачи; baseline.json — то же по сессиям до Archivist
    usage.json            как часто каждая запись встречалась, применялась, помогала или вводила в заблуждение
    analyses.jsonl        каждый запуск анализа: исход, сколько записано, стоимость, ошибки
    codex/                события hooks, дайджесты задач, очередь и бюджеты анализа Codex
    opencode/             очищенные дайджесты, очередь, результаты и бюджеты анализа OpenCode
    memory-<store>.json   что отправлено во внешнюю память из этой копии проекта
.claude/rules/archivist/
  core.md                 то, что агент читает в начале каждой сессии (не больше 60 строк и 6000 символов);
                          решения здесь — заголовок и первая фраза, целиком они в ADR
  <area>.md               факты и решения для части кода, с `paths:` во frontmatter: Claude Code загружает
                          файл, только когда агент открывает подходящие файлы (не больше 40 строк и 3000 символов)
.claude/skills/archivist-*/SKILL.md
                          процедуры для Claude Code (релиз, миграция), после повторения и ревью
.agents/skills/archivist-*/SKILL.md
                          процедуры для Codex
.opencode/skills/archivist-*/SKILL.md
                          процедуры для OpenCode
```

`ledger.jsonl` — общий источник истины для Claude Code, Codex и OpenCode; индекс, ADR, правила и skills генерируются из него, руками их не правят. Каждый адаптер обновляет представления своей платформы. Claude Code загружает правила с `paths:` при открытии подходящих файлов; в Codex такие записи ищут через навык `recall`, автоматической загрузки по glob нет. OpenCode подставляет ограниченную подборку правил для затронутых файлов перед следующим запросом модели.

Чтобы делиться знаниями с командой, можно коммитить `.archivist/` и сгенерированные правила и skills используемых платформ, предварительно проверив содержимое. Если знания должны оставаться локальными, добавь эти каталоги в `.gitignore`. Данные сессий (промпты, id, расход токенов и дайджесты Codex и OpenCode) остаются в `.archivist/.local/`, автоматически исключённом из git. В журнал пишется сам факт, доказательство в коде и id сегмента задачи. В `core.md` попадают только команды, ловушки и ссылки на решения. Обзоров кодовой базы там нет, потому что они не ускоряют агента и удорожают каждую сессию ([почему](PLAN.md#13-эмпирика-что-реально-экономит-ресурсы)).

## Установка

Для всех платформ нужен Node.js ≥ 20. Выбери пакет для своего агента; при совместном использовании они работают с одной `.archivist/`.

### Claude Code

Нужен Claude Code ≥ 2.1.290 (терминал, десктоп или VS Code). В сессии:

```
/plugin install archivist --marketplace BeeTrain/archivist
```

Или в два шага: `/plugin marketplace add BeeTrain/archivist`, затем `/plugin install archivist@archivist`. После установки выполни `/reload-plugins` или начни новую сессию.

Подготовка проекта (необязательно): `archivist init` из Bash-инструмента сессии, где `bin/` плагина есть в PATH.

Удаление: `archivist uninstall` убирает сгенерированные правила и skills (написанное руками не трогает), `--purge` удаляет ещё и `.archivist/`. Затем `/plugin uninstall archivist@archivist`.

### Codex

Нужен Codex с поддержкой плагинов и command hooks. В терминале:

```bash
codex plugin marketplace add BeeTrain/archivist
codex plugin marketplace upgrade archivist
codex plugin add archivist-codex@archivist
```

Включи плагин и разреши его hooks в настройках Codex. В нужном проекте вызови навык `setup`: он создаёт `.archivist/`, записывает команды проекта и запускает диагностику. Начни новый чат и вызови `collection`, чтобы проверить доставку событий. Для обновления повтори последние две команды установки.

Знания можно сохранять сразу через `remember` и `decide`. Чтобы включить фоновый анализ, из каталога проекта выполни команды, подставив путь к установленному пакету:

```bash
node /absolute/path/to/plugin-codex/bin/archivist analysis enable
node /absolute/path/to/plugin-codex/bin/archivist analysis status
```

Для анализа нужен установленный и авторизованный Codex CLI. Навык `panel` открывает панель рядом с чатом; `triage` разбирает предложения. Подробности — в [docs/codex.md](docs/codex.md).

Удаление: `node /absolute/path/to/plugin-codex/bin/archivist uninstall`, затем отключи или удали плагин в настройках Codex.

### OpenCode

Нужен OpenCode **2.2.5 (V2)**; интерфейс с индикатором и панелью предназначен для OpenCode Desktop. Используй локальный каталог `plugin-opencode/` из этого репозитория. Пакет содержит собранные файлы. После изменения исходников сначала выполни сборку, описанную ниже.

Добавь путь к пакету в `plugins` файла `opencode.jsonc` нужного проекта, сохранив остальные настройки:

```json
{
  "plugins": ["/absolute/path/to/archivist/plugin-opencode"]
}
```

Открой проект в OpenCode и вызови `/archivist init`, затем `/archivist analysis status`. Плагин добавляет инструмент `archivist` и навыки `archivist-recall`, `archivist-remember`, `archivist-decide`, `archivist-triage`. Фоновый анализ уже включён; чтобы выключить его, вызови `/archivist analysis disable`. Сохранённые знания при этом остаются доступны агенту.

Для индикатора 📚 и панели при установке только в проект добавь в `plugins` глобального `~/.config/opencode/opencode.jsonc` путь к **подкаталогу `ui/`** того же пакета:

```json
{
  "plugins": ["/absolute/path/to/archivist/plugin-opencode/ui"]
}
```

Эта запись подключает только интерфейс; сбор и анализ остаются включены лишь в проектах с основным плагином. Если основной пакет `plugin-opencode/` подключён глобально для всех проектов, его интерфейс загрузится вместе с ним — отдельная запись `ui/` не нужна. Не добавляй оба варианта одновременно.

Панель открывается по индикатору или `/archivist-panel`. Данные обновляются каждые две секунды; при переключении проекта показываются его записи. GUI API экспериментальный, сборка проверена на версии 2.2.5. Дополнительные варианты подключения — в [инструкции OpenCode](plugin-opencode/README.md).

Удаление: из каталога проекта выполни `node /absolute/path/to/plugin-opencode/bin/archivist uninstall`, затем убери основной пакет и запись `ui/`, если она есть, из настроек OpenCode. При установке копированием в `.opencode/plugins/` удали также каталог установленного пакета.

На всех платформах `uninstall` удаляет представления выбранной платформы, а `--purge` — общую `.archivist/`, включая знания и локальные данные всех адаптеров. Команда `init` извлекает команды сборки, тестов и линта из `package.json`, `Makefile`, `justfile`, `Cargo.toml`, `go.mod`.

### Из исходников

```bash
npm install
```

```bash
npm run build
```

Сборка обновляет `plugin/hooks/register.js` (мод Claude Code), `plugin/bin/archivist` (общий CLI), `plugin-codex/bin/archivist` (CLI и hooks Codex), а также `plugin-opencode/index.js`, `plugin-opencode/bin/archivist` и `plugin-opencode/ui/gui-experimental.cjs` (сервер, CLI и интерфейс OpenCode). Собранные файлы лежат в git, чтобы подключение не требовало сборки. Для сборки GUI нужны Node.js 20.19+ или ≥ 22.12. Запуск Claude Code с плагином из рабочей копии:

```bash
claude --plugin-dir ./plugin
```

В десктоп-приложении путь к `plugin/` передаётся через переменную `CLAUDE_CODE_PLUGIN_DIRS`.

Для Codex пакет из рабочей копии находится в `plugin-codex/`, каталог маркетплейса — в `.agents/plugins/marketplace.json`. Перед подключением выполни `npm run validate:codex`. Сборка не устанавливает пакет в профиль Codex и не обновляет установленную копию в кэше.

Для OpenCode перед подключением выполни `npm run validate:opencode`. В репозитории уже есть `opencode.jsonc` с путём к `plugin-opencode/`; интерфейс Desktop подключается отдельно, как описано выше. Если пакет скопирован в другой проект, после сборки обнови и установленную копию.

## Команды

### Claude Code

В сессии доступны команды мода и skills:

| Команда | Что делает |
|---|---|
| `/archivist` | полный отчёт по последней проанализированной задаче |
| `/archivist status` | сколько записей по типам, сколько ждёт ревью, есть ли открытая задача |
| `/archivist:triage` | skill: агент сам проверяет технические предложения по коду и разбирает их, а тебя спрашивает только про решения и удаления |
| `/archivist review` | предложения, которые анализатор не решился применить сам |
| `/archivist apply <n\|1,3\|all>` | записать предложения как есть |
| `/archivist skip <n\|1,3\|all>` | отклонить; та же идея больше не предлагается |
| `/archivist health` | одна сводка о работе в этом проекте: база, анализы за неделю, сбои, расход, какие записи не используются, находки `lint` — и что сделать |
| `/archivist stats` | метрики последних задач против baseline и как работает каждая запись |
| `/archivist recall <слова>` | записи по теме: дешевле, чем искать по коду |
| `/archivist edit <id> [--title "…"] [--content "…"] [--why "…"] [--paths "…"]` | поправить записанное; пустой `--paths ""` снимает привязку к путям |
| `/archivist deprecate <id> --reason "…"` | вывести запись из правил (в журнале остаётся с причиной) |
| `/archivist log` | диагностика фонового анализа в текущем проекте |
| `/archivist memory [status\|sync\|clear]` | внешняя память: куда идут записи, сверить сейчас, убрать свои элементы |
| `/archivist:remember [что]` | skill: записать команду или ловушку вручную |
| `/archivist:decide [что]` | skill: записать решение как ADR (с причиной и отвергнутыми вариантами) |

### Codex

Попроси агента вызвать навык по имени:

| Навык | Что делает |
|---|---|
| `setup` | подготовка проекта и диагностика |
| `panel` | живая панель с записями, поиском, очередью ревью и состоянием анализа |
| `recall` | поиск знаний перед разведкой проекта |
| `remember` | сохранить команду или ловушку |
| `decide` | записать решение как ADR |
| `triage` | проверить и разобрать предложения; решения и удаления согласовать с пользователем |
| `collection` | проверить сбор событий и анализ, сохранить знания из текущего чата |

В Codex операции с базой выполняются через навыки и общий CLI; команды `/archivist …` в его чате не регистрируются. Дополнительные команды пакета Codex из каталога проекта:

| Команда | Что делает |
|---|---|
| `node <plugin-root>/bin/archivist collection` | сводка доставленных событий и состояния сбора |
| `node <plugin-root>/bin/archivist analysis [status\|enable\|disable\|run]` | состояние, включение, выключение или обработка очереди анализа с учётом паузы и бюджетов |
| `node <plugin-root>/bin/archivist panel --root <проект>` | локальная панель; процесс нужно оставить работающим |

Здесь `<plugin-root>` — путь к пакету `plugin-codex/`.

### OpenCode

В сессии доступна команда `/archivist <подкоманда>` и инструмент `archivist` с теми же подкомандами. В отличие от Claude Code, `/archivist` без аргументов показывает **статус**, а отчёт запрашивается явно через `report`.

| Команда | Что делает |
|---|---|
| `/archivist` / `/archivist status` | количество записей и предложений на ревью |
| `/archivist init` | подготовить проект и записать команды из манифестов |
| `/archivist recall <слова>` | найти знания по теме |
| `/archivist review [--json]` | показать очередь ревью; `--json` возвращает стабильные id для разбора агентом |
| `/archivist apply <n\|id\|all>` / `/archivist skip <n\|id\|all>` | принять или отклонить предложения |
| `/archivist add …` / `/archivist edit <id> …` / `/archivist deprecate <id> --reason …` | записать, поправить или вывести знание из действующих правил; аргументы — как в общем CLI |
| `/archivist report` | последний отчёт проекта из общего каталога отчётов; в панели отдельно доступен последний анализ OpenCode |
| `/archivist health` / `/archivist stats` | общие сводки базы и метрик; состав диагностики отличается от мода Claude Code |
| `/archivist lint` / `/archivist gc` / `/archivist render` / `/archivist doctor` | проверка и обслуживание базы, перегенерация правил, диагностика установки |
| `/archivist analysis [status\|enable\|disable]` | состояние, включение или выключение фонового анализа |
| `/archivist-panel` | открыть панель в OpenCode Desktop; также открывается нажатием на 📚 |

Результат `/archivist …` добавляется в очередь сессии без запуска модели; агент получает его при следующем продолжении. Если результат нужен агенту сразу, используй инструмент `archivist`. Команда `/archivist-panel` открывает интерфейс непосредственно.

Попроси агента вызвать навык по имени:

| Навык | Что делает |
|---|---|
| `archivist-recall` | найти знания перед разведкой проекта |
| `archivist-remember` | сохранить точную команду или неочевидную ловушку |
| `archivist-decide` | записать согласованное решение и его причины как ADR |
| `archivist-triage` | проверить технические предложения по коду; решения и удаления согласовать с пользователем |

Команды `memory status/sync/clear` и отдельный журнал `log` пока не перенесены; `baseline` для OpenCode не реализован. Веб-панель `panel` и удаление `uninstall` запускаются из терминала через `node <plugin-root>/bin/archivist`, где `<plugin-root>` — путь к `plugin-opencode/`.

### Общий CLI

В Claude Code CLI находится в `plugin/bin/archivist` и доступен агенту в PATH как `archivist`. В Codex и OpenCode используй `node <plugin-root>/bin/archivist <команда>` с путём к соответствующему пакету: он сам выбирает профиль платформы. Общий CLI из `plugin/bin/archivist` также принимает `--target codex` или `--target opencode`. Если не указано иначе, команды ниже работают на всех трёх платформах; `--root <проект>` позволяет выбрать каталог проекта.

| Команда | Что делает |
|---|---|
| `archivist init` | создаёт `.archivist/` и записывает команды из манифестов проекта |
| `archivist status` | состояние базы знаний |
| `archivist report [file]` | последний отчёт или указанный |
| `archivist review [--json]` / `apply <n\|id>` / `skip <n\|id>` | ревью предложений, как в сессии; `--json` и id — для разбора агентом |
| `archivist add --type <command\|gotcha\|decision> --title … --content … [--why …] [--paths …] [--evidence …]` | записать факт вручную; решению нужен `--why` |
| `archivist edit <id> …` / `deprecate <id> --reason …` | поправить или вывести запись, как в сессии |
| `archivist recall <слова>` | поиск по записям (BM25); агент может вызывать сам, вместо разведки |
| `archivist baseline [--before <дата>]` | только Claude Code: метрики сессий проекта до Archivist, из их транскриптов |
| `archivist health` | состояние базы, анализов и записей; в Claude Code — аналог `/archivist health` без лога мода; очередь Codex и OpenCode проверяют через `analysis status`, сбор Codex — через `collection` |
| `archivist stats` | метрики и использование записей; сравнение задач с baseline собирается адаптером Claude Code |
| `archivist gc [--days 60] [--apply]` | записи без признаков использования за срок; `--apply` выводит их из правил (в журнале остаются) |
| `archivist lint` | дубли и противоречия, stale, решения без причины, переполнение бюджета |
| `archivist render` | перегенерирует представления из журнала |
| `archivist doctor` | проверяет Node, конфиг, журнал и бюджеты правил выбранной платформы; в профиле Claude Code — ещё его версию |
| `archivist uninstall [--purge]` | убирает представления выбранной платформы; `--purge` — и общую `.archivist/` |

## Настройки

Все адаптеры читают `.archivist/config.json`. Общие настройки и значения по умолчанию:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | выключатель для проекта |
| `language` | `"auto"` | язык записей: `auto` — как в промптах пользователя, иначе например `"Russian"` |
| `analyzer.idleSeconds` | `90` | сколько тишины после хода считать концом задачи |
| `analyzer.minToolCalls` | `5` | порог: задачи меньше этого без правок и ошибок пропускаются |
| `analyzer.maxTokensPerDay` | `3000000` | дневной бюджет анализа во взвешенных токенах (чтение из кэша считается как 0.1) |
| `budgets.coreLines` / `budgets.coreChars` | `60` / `6000` | лимит `core.md`: сверх него записи с худшей историей использования уходят в `INDEX.md` (доступны через `recall`) |
| `budgets.pathFileLines` / `budgets.pathFileChars` | `40` / `3000` | лимит каждого файла правил для части кода |
| `rules.decisions` | `"compact"` | решения в `core.md`: `compact` — заголовок и первая фраза, `full` — целиком |
| `rules.files` | `true` | создавать правила и skills выбранной платформы; `false` отключает их генерацию, сохраняя журнал, индекс и ADR |
| `privacy.excludePaths` | `.env*`, `**/secrets/**`, `**/*.pem`, … | файлы, которые не попадают ни в журнал, ни в модель, ни в доказательства записей |
| `review.expireDays` / `review.expireTasks` | `14` / `20` | неразобранные предложения удаляются через столько дней или задач |

Настройки Claude Code:

| Ключ | По умолчанию | Смысл |

| `analyzer.reflect` | `"fork"` | `fork` — спросить основную модель поверх её контекста; `digest` — только haiku по дайджесту |
| `analyzer.forkMaxContextTokens` | `300000` | при большем живом контексте reflect идёт по дайджесту, без `fork`: цена `fork` растёт с сессией |
| `analyzer.curateModel` | `"haiku"` | модель для курирования |
| `analyzer.maxRateLimitPercent` | `90` | не анализировать, если окно лимита заполнено сильнее |
| `analyzer.useCredits` | `false` | анализировать и при заполненном окне подписки (`five_hour`, `seven_day`): анализ тогда идёт за счёт usage credits, а без них падает. Лимит трат шлюза (`spend_limit`) держит всегда |
| `apply.autoConfidence` | `0.8` | порог уверенности для применения без ревью |
| `apply.autoTypes` | `command, gotcha, decision` | какие типы можно применять без ревью |
| `review.promoteOnRepeat` | `true` | команда или ловушка, предложенная повторно, пока первое предложение ждёт, применяется сама |

| `memory.server` / `memory.project` | `"auto"` | сервер памяти, как его показывает `/mcp`, и имя проекта в памяти (по умолчанию из `git remote`) |
| `report.mode` | `"quiet"` | `quiet` — статус, toast, строка под ответом; `rewake` — сессия получает ход с отчётом (стоит один короткий ход модели) |
| `report.toastMs` | `15000` | сколько держится toast |

Настройки Codex:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `codex.enabled` | `false` | включить фоновый анализ в проекте; также меняется через `analysis enable` / `disable` |
| `codex.model` | `""` | модель отдельного запуска Codex CLI; пустое значение использует стандартную модель CLI |
| `codex.timeoutSeconds` | `120` | время ожидания ответа CLI |
| `codex.maxCallsPerDay` | `20` | максимум вызовов анализа в день |

Codex всегда анализирует дайджест и отправляет результаты на ревью: `analyzer.reflect`, `analyzer.curateModel`, `apply.auto*` и `review.promoteOnRepeat` не меняют это поведение. Параметры окон лимитов, внешней памяти и отчётов Claude Code к адаптеру Codex не применяются. Пауза и дневной токенный бюджет общие по настройкам; в Codex перед вызовом резервируется 50 000 условных токенов, после успешного ответа — фактический расход. Подробнее об ограничениях бюджета — в [docs/codex.md](docs/codex.md#фоновый-анализ).

Настройки OpenCode:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `opencode.enabled` | `true` | собирать дайджест и запускать фоновый анализ; также меняется через `analysis enable` / `disable` |
| `opencode.model` | `""` | модель анализа в формате `provider/model`; пустое значение использует модель текущей сессии |
| `opencode.timeoutSeconds` | `120` | время ожидания анализа |
| `opencode.maxCallsPerDay` | `20` | максимум попыток анализа в день, включая повторы |

OpenCode анализирует дайджест и отправляет все изменения на ревью: `analyzer.reflect`, `analyzer.curateModel`, `apply.auto*` и `review.promoteOnRepeat` это не меняют. Пауза задаётся через `analyzer.idleSeconds`, дневной токенный бюджет — через `analyzer.maxTokensPerDay`. Перед анализом резервируется 50 000 условных токенов. API генерации 2.2.5 возвращает только текст, поэтому после успешного ответа расход оценивается по длине запроса и ответа; точное число токенов и денежную стоимость этот адаптер не получает. Число попыток ограничивается отдельно через `opencode.maxCallsPerDay`.

Сбор ограничен основной сессией текущего каталога. При `opencode.enabled: false` новый дайджест не собирается и анализ не запускается, но сохранённые знания остаются доступны. Параметры внешней памяти, окон лимитов и отчётов Claude Code к OpenCode не применяются.

## Внешняя память

В Claude Code, если в сессии подключён плагин долгосрочной памяти (сейчас поддерживается OpenViking), Archivist кладёт туда свои записи. Их видят другие агенты и плагины. Журнал остаётся источником истины, память получает его копию: новые и изменённые записи туда дописываются, выведенные из оборота — удаляются. Каждый элемент подписан проектом, id записи и временем изменения, поэтому клоны, ветки и коллеги с общим сервером не перезаписывают друг друга.

Адаптеры Codex и OpenCode не синхронизируют внешнюю память. Общие знания всех трёх платформ в одном проекте доступны через `.archivist/`.

Принцип хранения для любой системы памяти, формат элемента и правила синхронизации — в [docs/memory.md](docs/memory.md).

## Разбирать очередь не обязательно

В Claude Code на ревью уходит то, что анализатор не применил автоматически: неуверенные факты, процедуры, записи с замаскированными секретами и изменения, требующие согласования. В Codex и OpenCode на ревью идут все результаты анализа. Вникать в каждое техническое предложение не нужно:

- **Навык `triage`** (`/archivist:triage` в Claude Code, `archivist-triage` в OpenCode) — агент проверяет команды и ловушки по коду и разбирает их сам. Тебя он спрашивает только о решениях и удалениях, по строке на понятном языке. В панели OpenCode предложения также можно принять или отклонить вручную.
- **Повтор подтверждает в Claude Code.** Если команду или ловушку предложили снова, пока первое предложение ждёт, она записывается сама. Решения и удаления так не применяются. В Codex и OpenCode повторные предложения также требуют ревью.
- **Срок жизни.** Неразобранное предложение удаляется через 14 дней или 20 задач. Важный факт может появиться снова; в Codex и OpenCode его всё равно нужно подтвердить через навык разбора ревью, CLI или панель OpenCode.

## Стоимость и приватность

- В Claude Code анализ запускается после нетривиальных задач; расход каждого шага указан в отчёте и учитывается в дневном бюджете. `fork` читает закэшированный контекст сессии: учитываются чтение из кэша и короткий ответ, затем курирование на haiku.
- В Codex анализ по умолчанию выключен и не вызывает модель. После включения расходуются лимиты авторизованного Codex CLI; действуют дневные бюджеты вызовов и токенов. При ошибке возможны до трёх попыток с паузой 15 минут. Без текста запроса модель не вызывается.
- В OpenCode анализ включён по умолчанию и использует настроенного провайдера модели. Действуют дневной лимит попыток и бюджет с оценкой токенов; при ошибке возможны до трёх попыток с паузой 15 минут. Простые задачи и задачи без текста запроса пропускаются. Отключить анализ можно через `opencode.enabled: false` или `/archivist analysis disable`.
- То, что принадлежит сессии (`.archivist/.local/`: отчёты с текстом промптов, id сессий, метрики), в git не попадает: первая же запись в `.archivist/` создаёт `.archivist/.gitignore` со строкой `.local/`, даже если `archivist init` не запускали.
- В Claude Code данные передаются модели через авторизацию сессии и, если подключён плагин памяти, в эту память. Внешняя память получает только очищенные записи, без отчётов, промптов и метрик; синхронизация отключается через `memory.enabled: false`.
- В Codex без анализа сохраняются только метаданные событий, идентификаторы хешируются. После включения очищенный дайджест и релевантные знания передаются отдельному процессу Codex CLI. Полные результаты инструментов, патчи и транскрипты не сохраняются; подробности — в [docs/codex.md](docs/codex.md#данные-и-приватность).
- В OpenCode очищенные запросы и ответы, цели инструментов, краткие ошибки и метрики остаются в `.archivist/.local/opencode/`. Для анализа модели передаются дайджест и релевантные знания. Содержимое прочитанных файлов, патчи и рассуждения не собираются. Панель читает данные текущего проекта через сервер OpenCode и не обращается к модели. Телеметрии Archivist нет ни на одной платформе.
- Секреты (ключи API, токены, пароли в присваиваниях, приватные ключи, пароли в URL) маскируются в командах журнала, в материале для модели и в тексте записей. Запись, для которой понадобилось маскирование, уходит на ревью.
- Записи с исчезнувшими доказательствами (файлы удалены или переименованы) помечаются в `INDEX.md` как stale и не попадают в правила, пока файл не вернётся или запись не обновят.

## Разработка

```bash
npm run check
```

`check` запускает проверку типов в трёх конфигурациях: с Node для CLI и серверных адаптеров, в окружении мода Claude Code без Node по типам `types/claude-code/`, а также для GUI OpenCode с Solid и DOM. Затем идут тесты (vitest) и сборка всех пакетов, включая визуальную часть OpenCode. Валидация пакетов:

```bash
npm run validate
npm run validate:codex
npm run validate:opencode
```

`validate` проверяет плагин Claude Code, `validate:codex` — структуру пакета Codex и пути его hooks и skills, `validate:opencode` — серверную и визуальную части OpenCode, вспомогательный пакет интерфейса, CLI и skills. Живую доставку событий Codex проверяют после установки через `collection`, анализ Codex и OpenCode — через `analysis status` и панели.

Eval-кейсы Claude Code лежат в `plugin/evals/`:

- ловушка записывается и привязывается к путям;
- решение становится ADR;
- личное и временное не записывается;
- секрет не попадает в файлы.

Прогоны тратят лимиты твоей подписки, `claude` должен быть залогинен. Skills вызывают CLI через Bash, поэтому его нужно разрешить:

```bash
claude plugin eval plugin --allow-tools Bash
```

Фоновый анализ мода eval не покрывает: прогоны идут в `claude -p`, а анализ запускается по таймеру после простоя. Его проверяют вживую через `/archivist log` и `/archivist stats`.

Тесты адаптера Codex покрывают нормализацию событий, исключение содержимого, дедупликацию, изоляцию представлений, очередь и вызов анализа. Валидатор пакета не заменяет проверку загрузки и реальных payload hooks в клиенте.

Тесты OpenCode покрывают сбор и фильтрацию контекста, очередь, отмену устаревшего анализа, бюджеты, изоляцию проектов и представлений, данные панели и защиту от применения изменившегося предложения. Отдельно проверены загрузка в OpenCode 2.2.5, полный цикл анализа с локальной тестовой моделью и отображение панели в Desktop.

CI (`.github/workflows/ci.yml`) гоняет проверку типов, тесты и сборку, проверяет актуальность собранных файлов в `plugin/`, `plugin-codex/` и `plugin-opencode/`, валидирует пакеты Codex и OpenCode, плагин Claude Code и его маркетплейс.

Структура:

```
src/core/       модель данных, журнал, валидация, рендер — общий TS для всех платформ
src/analyzer/   сигналы, дайджест, промпты, разбор ответа модели, пайплайн, отчёт
src/adapters/claude/mod/register.ts   мод Claude Code: события → журнал → анализ → отчёт
src/adapters/codex/   hooks Codex, сбор событий, очередь и анализ через Codex CLI
src/adapters/opencode/   плагин V2: события, контекст, анализ, данные панели и GUI
src/cli/        CLI на Node
plugin/         пакет Claude Code (манифест, hooks.json, register.js, bin/, skills/)
plugin-codex/   пакет Codex (манифест, hooks.json, bin/, skills/)
plugin-opencode/   пакет OpenCode 2.2.5 (package.json, index.js, bin/, skills/, ui/)
.claude-plugin/marketplace.json   каталог маркетплейса Claude Code
.agents/plugins/marketplace.json каталог маркетплейса Codex
spikes/         код исследований этапа 0
```

Ограничения среды мода Claude Code, которые важны при правках `register.ts`:

- в моде нет Node, весь ввод-вывод идёт через `$`;
- `$` можно передавать только функциям верхнего уровня этого файла;
- имя события в `on()` должно быть литералом;
- имена команд мода не получают префикс плагина;
- при перезагрузке мода сбрасываются таймеры.

Подробнее о среде Claude Code — в [docs/spikes.md](docs/spikes.md), о hooks, анализе и ограничениях Codex — в [docs/codex.md](docs/codex.md), о подключении и интерфейсе OpenCode — в [plugin-opencode/README.md](plugin-opencode/README.md).
